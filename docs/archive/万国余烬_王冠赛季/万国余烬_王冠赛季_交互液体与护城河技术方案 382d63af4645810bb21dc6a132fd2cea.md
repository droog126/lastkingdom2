# 万国余烬：王冠赛季 交互液体与护城河技术方案

**版本**：V2.0 重构设计版

**适用范围**：可交互水体、护城河、挖沟引水、排水、涉水、游泳、溺水、桥梁和地形联动

**最后更新**：2026-06-17

**文档定位**：本文件是地形系统的液体专项。目标是支持“挖护城河”这种可交互战术水体，但不做昂贵的真实全流体模拟。

---

## 1. 核心结论

本项目的液体系统采用 **水源锚点 + 水体覆盖层 + 低分辨率格子水量 + 事件式同步**。

它不是完整物理流体，也不是纯贴图水面。

玩家可以：

- 挖沟引水，形成护城河。
- 堵水、排水、填沟。
- 架桥跨水。
- 用浅水拖慢敌人和推车。
- 用灵脉/法术改变局部水体状态。
- 破坏桥梁或水闸改变路线。

玩家不能：

- 无限复制水。
- 把整张地图淹没。
- 造无解水牢。
- 用客户端生成真实水量。
- 把火种/神器丢进不可达深水。

---

## 2. 为什么不做完整流体

真实流体模拟会带来：

- 服务端计算重。
- 网络同步昂贵。
- 结果难预测。
- 玩家容易制造不可控地图破坏。
- PVP 可读性下降。

本项目需要的是“护城河、浅水、引水、排水、涉水、桥梁”的战术体验，所以用近似模型更合适。

---

## 3. 分层模型

| 层 | 内容 | 权威方 | 说明 |
| --- | --- | --- | --- |
| 水源锚点 | 河流、湖、井、灵脉、水闸 | 服务端 | 决定水从哪里来 |
| 水体格子 | 低分辨率水量、水位、流向 | 服务端 | 控制是否有水、深浅和流动 |
| 水面表现 | mesh、shader、泡沫、涟漪 | 客户端 | 只表现，不决定玩法 |
| 交互覆盖层 | 沟、堤、桥、水闸、填土 | 服务端 | 玩家改造 |
| 移动影响 | 涉水、游泳、推车阻力、溺水 | 服务端 | 进入角色移动系统 |

---

## 4. 水体格子

液体使用低分辨率网格，不跟地形 mesh 一一对应。

推荐：

- 每格 2m 或 4m。
- 每格记录水量和水位。
- 只在“活跃水区”更新，不全图每帧更新。
- 服务端 2-5Hz 更新液体扩散，客户端插值水面表现。

```rust
pub struct WaterCell {
    pub cell_id: WaterCellId,
    pub water_amount: f32,
    pub water_level: f32,
    pub ground_height: f32,
    pub flow_dir: Vec2,
    pub state: WaterCellState,
}
```

水体状态：

```rust
pub enum WaterCellState {
    Dry,
    WetMud,
    Shallow,
    Deep,
    Blocked,
    Source,
    Drain,
}
```

## 5. 水源与水量守恒

水不是无限凭空出现。

| 来源 | 规则 |
| --- | --- |
| 河流 | 固定水源，输出有上限 |
| 湖泊 | 可作为大水源，但不能被抽干到破坏地图 |
| 水井 | 小水源，主要供生存和局部填水 |
| 灵脉水 | 魔法水源，可被法术/污染影响 |
| 雨水事件 | 临时增加湿地和浅水 |
| 水闸 | 控制水流进入沟渠 |

守恒口径：

- 基础水源有每秒最大输出。
- 护城河水量来自水源输出或已有水体迁移。
- 水体蒸发、渗漏和排水作为回收路径。
- 水不能通过反复挖沟无限复制。

## 6. 挖护城河流程

玩家想挖护城河，需要完成两件事：

1. 挖出可容水沟渠。
2. 连接水源或人工注水。

流程：

```
Dig Trench
  -> Server validates depth/width/escape/route
  -> Creates TrenchOverlay + WaterChannelTag
  -> Player opens canal / builds sluice
  -> Server links channel to WaterSource
  -> Water simulation fills cells over time
  -> Client renders water surface and wet edges
```

护城河不是瞬间生成满水，它需要填充时间。这个时间会形成攻防窗口。

---

## 7. 沟渠规格

| 类型 | 深度 | 宽度 | 水体状态 | 玩法 |
| --- | --- | --- | --- | --- |
| 排水沟 | 0.3-0.6m | 1-2m | WetMud/Shallow | 减速、导水 |
| 浅护城河 | 0.6-1.2m | 2-4m | Shallow | 阻推车、减速 |
| 深护城河 | 1.2-2.0m | 3-6m | Deep | 需桥、游泳或攀爬 |
| 王权水渠 | 1.0-1.8m | 2-5m | Shallow/Deep + 灵脉 | 仪式和法术导流 |

MVP 推荐先做浅护城河和深护城河，不做复杂水下洞穴。

## 8. 流动规则

服务端按低频 tick 更新水体。

简单规则：

- 水从高水位流向低水位。
- 被墙、堤、闸门阻挡。
- 沟渠降低地面高度，因此更容易蓄水。
- 水量不足时只形成湿泥或浅水。
- 水量超过格子容量才向邻格扩散。

伪代码：

```
For each active water cell:
  capacity = cell_capacity(ground_height, channel_depth)
  overflow = max(0, water_amount - capacity)
  neighbors = lower_or_equal_neighbors_not_blocked()
  distribute overflow by slope and opening width
  apply leakage/evaporation
  update state Dry/WetMud/Shallow/Deep
```

## 11. 移动影响

| 水深 | 角色影响 | 推车/大件 | 战斗影响 |
| --- | --- | --- | --- |
| WetMud | 轻微减速 | 车轮阻力增加 | 闪避距离略降 |
| Shallow | 明显减速 | 推车很慢，可能卡住 | 疾跑蓄势变慢 |
| Deep | 需要游泳或攀爬 | 推车不可通行 | 不能正常攻击，施法受限 |
| SpiritWater | 受法术/灵脉影响 | 视规则 | 可导流法阵或结界 |
| PollutedWater | 持续危险 | 不建议通行 | 可能打断吟唱 |

重载规则：

- 重载进入深水风险更高。
- 超载不能游泳。
- 肩扛大件进入深水会强制掉落或禁止进入。
- 火种/神器进入深水会产生强提示，避免藏物。

---

## 12. 游泳、溺水与出水

MVP 不需要复杂游泳系统，但要有清晰规则。

| 状态 | 规则 |
| --- | --- |
| 涉水 | 还能走，速度降低 |
| 深水漂浮 | 进入游泳姿态，不能使用多数剑术 |
| 下沉风险 | 重载/超载/持大件触发 |
| 溺水计时 | 耐力耗尽后开始掉生命 |
| 出水 | 需要坡岸、攀爬点、桥边或队友救援 |

出水与坑洞逃生复用 `EscapeAnchor`：

- 岸边坡道。
- 木梯。
- 绳索。
- 根须阶。
- 桥边。
- 队友拉人。

---

## 13. 桥、坝、水闸

| 结构 | 功能 | 可破坏 |
| --- | --- | --- |
| 简易桥 | 跨越护城河 | 是 |
| 石桥 | 更耐久，允许推车 | 是 |
| 木坝 | 阻水、蓄水 | 是 |
| 石坝 | 高耐久阻水 | 是 |
| 水闸 | 控制水源输出 | 是，需要权限或工具 |
| 排水口 | 将水导向低区或排出战场 | 可堵塞 |

破坏规则：

- 破桥会中断路线，但不能让玩家永久困死。
- 破坝会释放水体，形成短期战术变化。
- 水闸开合必须有读条和声音。
- 高价值水闸应在小地图或局部 UI 显示。

---

## 14. 护城河反制

护城河不能成为无解防线。

反制方式：

- 架桥。
- 填沟。
- 破坝排水。
- 关闭或夺取水闸。
- 使用风歌术短暂越水。
- 使用根须术生成临时踏点。
- 用月影剑/身法从窄点突入。
- 绕路攻击水源。

服务端必须保证至少存在一种非神器级反制路径。

---

## 15. 防滥用规则

禁止：

- 淹没出生点。
- 淹没王座唯一入口。
- 淹没 Boss 主战场唯一出口。
- 把火种/神器藏进深水不可达点。
- 让玩家在深水中无法出水。
- 用水体无限刷移动/资源/伤害。
- 客户端本地生成权威水位。

限制：

- 每个国家可维护的活跃水体格子有上限。
- 水源输出有上限。
- 护城河宽度和深度受预算限制。
- 深水会产生明显小地图/世界提示。

---

## 16. 渲染

水体渲染是表现层，不决定水位。

表现：

- WetMud：湿泥反光、脚印、车辙。
- Shallow：浅水面、波纹、脚步水花。
- Deep：更深蓝绿水面、边缘泡沫。
- SpiritWater：灵脉青流线。
- PollutedWater：污染红粉裂纹和暗色泡沫。

渲染数据来自 `WaterCellsChangedMsg` 和水体快照。

客户端可插值水面高度，但不能改变服务端 `water_level`。

小地图显示：

- 水源。
- 护城河。
- 深水危险。
- 桥梁。
- 水闸。

UI 提示：

- `浅水：疾跑蓄势变慢`
- `深水：重载无法游泳`
- `需要桥梁或攀爬点`
- `水闸开启中`

- `自动脱困会掉落神器/火种`

## 18. 网络同步

不要同步每帧水面 mesh。同步水体格子变化。

同步内容：

- cell id。
- water amount。
- water level。
- state。
- flow direction。
- reason。

频率：

- 活跃水体 2-5Hz。
- 非活跃水体只发状态变化。
- 客户端用插值平滑水面高度。

## 20. 验收标准

- 玩家能挖沟连接水源，水会随时间填充为护城河。
- 护城河能减速玩家、阻挡推车和改变攻防路线。
- 玩家可以架桥、填沟或夺取水闸反制护城河。
- 玩家掉入深水后能通过岸坡、攀爬点、桥边或救援出水。
- 火种/神器不能被藏进不可达深水。
- 水体状态由服务端权威控制，客户端只做表现插值。
