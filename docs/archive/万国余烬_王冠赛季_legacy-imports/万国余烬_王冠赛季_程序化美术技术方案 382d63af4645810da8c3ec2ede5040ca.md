# 万国余烬：王冠赛季 程序化美术技术方案

**版本**：V2.0 重构设计版

**适用范围**：程序化地形材质、资源节点、POI、地形改造覆盖层、剑轨/法阵 VFX、神器外观、小地图图层

**最后更新**：2026-06-17

**文档定位**：本文件定义程序化美术的技术管线。颜色遵守《美术风格与色彩规范》，渲染落地遵守《渲染技术方案》，地形规则遵守《地形系统技术方案》。

---

## 1. 设计目标

程序化美术不是把画面随机化，而是用规则生成 **可控、可读、可复现、可调参** 的视觉内容。

它要解决：

- 每局肉鸽地图不同，但不会失去美术统一性。
- 地形改造能自动生成边缘、破损、道路压痕和符文槽视觉。
- 法术、剑轨和神器不需要为每个技能手工堆资源。
- POI 可以模块化变化，同时保证入口、宝箱、怪物和关键路径合理。
- 小地图和战略图能从玩法数据自动生成图层。

程序化美术的红线：

- 不能生成影响公平性的隐藏路径或不可读障碍。
- 不能让皮肤、资源、神器、敌我颜色混淆。
- 不能客户端单独生成权威资源、碰撞或掉落。
- 不能为了变化破坏 PVP 可读性。

## 2. 管线总览

```
World Seed / Match Seed
  -> Procedural Art Config
  -> Biome Visual Fields
  -> Terrain Material Masks
  -> Resource Node Variants
  -> Mining Site Module Variants
  -> Cave Module Assembly
  -> POI Module Assembly
  -> Terrain Edit Visual Overlay
  -> VFX Runtime Generators
  -> Minimap Layers
```

生成分两类：

| 类型 | 生成位置 | 是否权威 | 示例 |
| --- | --- | --- | --- |
| Gameplay-bound visual | 服务端决定数据，客户端生成表现 | 服务端权威数据 | 资源节点、矿坑模块、POI、地形覆盖层、火种、神器 |
| Pure presentation | 客户端按 seed 或状态生成 | 非权威 | 草叶摆动、裂纹细节、粒子扰动、法阵符号排列 |

权威数据只传必要结构，客户端根据同一 seed 和配置生成细节表现。

## 5. Seed 规则

程序化美术必须可复现。

| seed | 用途 | 说明 |
| --- | --- | --- |
| `match_seed` | 世界生成基础 | 服务端发给客户端 |
| `biome_seed` | 地貌材质和颜色扰动 | 不改变通行规则 |
| `poi_seed` | POI 模块变体 | 不改变关键路径结果 |
| `resource_visual_seed` | 资源节点外观 | 不改变产量 |
| `artifact_visual_seed` | 神器裂纹和脉冲 | 不改变能力 |
| `vfx_seed` | 粒子扰动 | 纯表现，可本地不同 |

关键原则：**玩法结果由服务端 seed 和权威数据决定，纯视觉扰动可以客户端生成，但不能影响碰撞和拾取。**

## 7. 程序化地形材质

地形材质使用 biome 参数 + 噪声 + 高度/坡度/湿度 mask 生成。

| 输入 | 影响 |
| --- | --- |
| biome | 主色、辅色、资源点缀色 |
| height | 岩面、草地、坡面分布 |
| slope | 岩地暴露、道路可见性 |
| moisture | 泥地、浅水、苔藓 |
| magic_field | 灵脉、污染、王座脉冲 |
| edit_overlay | 新路、墙基、沟边、阵眼 |

输出：

- base color。
- roughness。
- emission mask。
- normal strength。
- minimap color。

美术规则：

- 普通地形低饱和。
- 灵脉和污染用 emission mask，但不能整块地图发光。
- 道路边缘必须比泥地更浅更干。
- 挖沟和墙基要自动生成磨损边缘。

## 8. 程序化资源节点与矿坑模块

资源节点采用“固定玩法数据 + 程序化外观变体”。矿坑模块同理，但它不是单个节点，而是一组入口、采矿槽、矿线、堆料点和危险表现。

```
ResourceNode(resource_id, amount, location, state)
  -> ResourceVisualRecipe
  -> variant mesh parts
  -> material tint
  -> weak point markers
  -> depleted state
```

| 资源 | 程序化变化 | 必须固定 |
| --- | --- | --- |
| 木材 | 树干弯曲、枝干数量、切面纹理 | 识别色和采集弱点 |
| 石料 | 石块形状、裂纹方向 | 岩灰主色 |
| 铁/铜/银 | 矿脉线位置、闪点频率 | 金属识别色 |
| 灵质 | 晶体高度、脉冲节奏 | 灵脉青 |
| 符文石 | 符文线排列 | 暗紫石体和亮紫刻线 |
| 星砂 | 闪烁点密度 | 星砂黄 |
| 灾变晶核 | 裂纹数量、污染粉尘 | 污染红粉 |

矿坑模块生成：

```
MiningSite(site_type, grade, slots, depletion, seed)
  -> entrance kit
  -> wall material set
  -> ore vein line density
  -> mining slot markers
  -> cargo pile points
  -> depletion overlay
  -> hazard VFX sockets
```

| 矿坑模块 | 程序化变化 | 必须固定 |
| --- | --- | --- |
| 露天矿坑 | 坑壁层次、矿线走向、木支架破损 | 入口、采矿槽、推车点 |
| 裂隙洞穴 | 出口冷光、岩缝宽度、粉尘 | 可达路径和逃生锚点 |
| 月纹矿坑 | 月相纹、冷辉强度、夜间闪点 | 月纹钢识别色和夜间提示 |
| 灵脉矿井 | 青色流线、脉冲节奏、晶体高度 | 灵压脉冲范围表现 |
| 灾变矿潮 | 污染裂纹、花核形态、红粉雾 | 危险边界和核心槽 |

枯竭态：

- 节点模型不瞬间消失。
- 变暗、裂开、切面暴露。
- 小地图图标降低优先级。
- 矿坑枯竭时，矿线密度下降，堆料点变少，采矿槽从高亮变为暗裂，不删除入口模块。

## 9. 地形改造覆盖层美术

地形改造是本项目最重要的程序化美术之一。

| 改造 | 程序化输出 |
| --- | --- |
| 挖沟 | 沟边磨损、土色渐变、阴影、脚印/车辙中断 |
| 木墙 | 模块长度、板材错位、绳结、受击裂纹 |
| 石墙 | 石块拼接、边角缺损、灰尘 |
| 桥 | 木板数量、间隙、支撑绳、断裂态 |
| 道路 | 压痕、边缘碎石、泥水过渡 |
| 符文槽 | 符号序列、发光节奏、资源插槽颜色 |
| 阵眼 | 圆环刻度、进度段、材料层级、破损裂纹 |

实现规则：

- 正式覆盖层只在服务端确认后生成。
- 客户端预览使用半透明材质，不能参与碰撞。
- 受损状态由耐久百分比驱动材质参数。
- 拆除/破坏时生成碎片 VFX，但碎片不产生真实资源，资源回流由服务端消息决定。

## 10. 程序化 POI

POI 使用模块化装配，不做完全随机建筑。

输入：

- POI 类型。
- seed。
- 入口数量。
- 宝箱点。
- 怪物点。
- 关键路径。
- 可破坏层。

装配流程：

```
Select footprint
  -> place required entrances
  -> place protected path
  -> place gameplay anchors
  -> fill decorative modules
  -> apply damage variants
  -> validate readability
```

| POI | 程序化部件 |
| --- | --- |
| 倒塌哨塔 | 断梁、平台角度、绳索、残旗 |
| 旧集市 | 摊位、布棚、木箱、车辙 |
| 月纹小祠 | 月相柱、浅水镜、月纹石板 |
| 灵井 | 圆井、悬浮水珠、灵脉线 |
| 遗迹门厅 | 巨门、碎柱、机关槽、符文灯 |
| 旧王巢穴 | 破冠拱门、王座残片、剑痕地面 |
| 星井遗迹 | 星盘、书页、井口环 |
| 灾变矿潮核心 | 晶簇、污染裂纹、粉尘柱、事件核心采矿槽 |

可读性校验：

- 入口从主要路径能看到。
- 宝箱点不被装饰遮挡。
- Boss 场地有足够移动空间。
- 高价值目标有轮廓和小地图提示。

## 10.1 程序化洞穴模块

洞穴模块使用固定玩法房间 + 程序化装饰，不随机改变关键路径。

```
CaveModule(cave_type, room_chain, seed)
  -> entrance kit
  -> room shell variants
  -> branch markers
  -> altar visual
  -> boss gate visual
  -> artifact material drop marker
```

| 洞穴 | 程序化部件 | 必须固定 |
| --- | --- | --- |
| 矿脉洞穴 | 支架、矿尘、矿线密度、碎石 | 出口、采矿槽、堆料点 |
| 遗迹封洞 | 符文门、机关柱、风化石 | 机关交互点、祭坛位置 |
| 旧王墓穴 | 破冠拱、剑痕、黑金石阶 | 王座残片房、Boss 门 |
| 星井深窟 | 星盘、书页、夜蓝雾 | 传送点、星井祭坛 |
| 灾变胎洞 | 污染裂纹、红粉雾、晶花 | 危险边界、核心槽 |

神器材料掉落必须有强轮廓，但不应和已唤醒的全局唯一神器混淆：材料是“小而尖锐的高价值物”，神器是“大件战略物”。

## 11. 程序化剑轨

剑轨用运行时 ribbon mesh，不为每个动作手做长动画贴图。

输入：

- 武器骨骼点。
- 招式类型。
- 流派。
- 速度。
- 是否满势疾跑。
- 是否命中/招架。

参数：

| 参数 | 作用 |
| --- | --- |
| `trail_width` | 剑轨宽度 |
| `trail_lifetime` | 残留时间 |
| `segment_count` | ribbon 分段 |
| `color_ramp` | 流派颜色渐变 |
| `alpha_curve` | 消失曲线 |
| `impact_pulse` | 命中短闪 |

规则：

- 轻击轨迹短而细。
- 重击轨迹更宽但前摇明显。
- 完美招架是短闪，不是大爆光。
- 风歌剑轨迹更弧，月影剑更冷更细，王庭剑更直，灰烬剑更短促。

## 12. 程序化法阵

法阵由圆环、刻度、符号、流线和中心图案组合。

```
SpellCircle(
  school,
  radius,
  cast_progress,
  danger_flag,
  faction,
  seed,
)
```

输出：

- outer ring。
- progress arc。
- rune marks。
- rotating inner ring。
- target fill。
- danger border。

法阵规则：

- 友方和敌方必须有形状差异，不只靠颜色。
- 大范围法术必须先显示边界。
- 读条法术进度用刻度环。
- 法阵符号可程序化排列，但学派主形状要固定，避免玩家看不懂。

## 13. 程序化神器外观

全局唯一神器采用“固定身份 + 程序化细节”。

固定：

- 轮廓。
- 主色：黑曜底 + 王冠金外圈。
- 专属副色。
- 关键挂点和持有姿态。

程序化：

- 裂纹数量。
- 漂浮碎片数量。
- 脉冲节奏。
- 内部光流方向。
- 来源事件痕迹。

| 来源 | 外观变化 |
| --- | --- |
| Boss 掉落 | 残热、破损、碎片环绕 |
| 遗迹封匣 | 符文封线、开匣尘光 |
| 王座唤醒 | 王冠金更强，余烬脉冲 |
| 天象事件 | 星砂粒子和天幕投影 |

能力不随外观随机变化。外观只表达来源和稀有感。

## 14. 程序化小地图图层

小地图不是截图，而是玩法数据图层。

图层：

| 图层 | 来源 |
| --- | --- |
| 地形底色 | biome map |
| 道路/浅水/泥地 | terrain material mask |
| 地形改造 | TerrainEditEntity |
| 资源筛选 | ResourceNode |
| 危险区 | Event / DamageVolume |
| 火种热区 | SovereignSpark reveal |
| 神器脉冲 | UniqueArtifact reveal |
| 国家补给圈 | Nation facility |
| 队伍标点 | CommandMarker |

规则：

- 火种显示模糊热区，不显示精确点，除非玩家近距离看到。
- 神器使用星冠强脉冲。
- 普通资源默认折叠，按筛选显示。
- 地形改造图层要和实际覆盖层同步。

## 15. 材质与 Shader 输入

程序化材质不应在 shader 中硬编码颜色。shader 读取实例参数。

```rust
pub struct ProceduralMaterialParams {
    pub base_color: Color,
    pub accent_color: Color,
    pub emission_color: Color,
    pub noise_seed: f32,
    pub wear: f32,
    pub activation: f32,
    pub danger: f32,
}
```

常用参数：

- `wear`：破损、磨损、枯竭。
- `activation`：法阵、符文槽、灵脉启用程度。
- `danger`：敌方危险边界或污染。
- `pulse_phase`：火种、神器、灵质脉冲。
- `faction_color`：友方/敌方/中立。

## 16. 性能预算

| 项目 | 高配 | 低配 |
| --- | --- | --- |
| 程序化草/小石装饰 | 6000 实例 | 1500 实例 |
| POI 装饰模块 | 100% | 60% |
| 剑轨分段 | 18 | 10 |
| 法阵分段 | 64 | 32 |
| 灵脉粒子 | 100% | 35% |
| 小地图图层刷新 | 10 Hz | 5 Hz |
| 地形覆盖层材质更新 | 10 Hz | 5 Hz |

降级策略：

1. 降装饰实例。
2. 降粒子。
3. 降剑轨/法阵分段。
4. 降 POI 小装饰。
5. 保留资源识别、敌我、火种、神器、危险区。

## 17. 开发优先级

程序化美术开发顺序：

1. 地形改造覆盖层：墙、沟、路、桥、符文槽、阵眼。
2. 剑轨和法阵生成器。
3. 资源节点变体和采集弱点。
4. 矿坑模块入口、采矿槽和枯竭表现。
5. 洞穴入口、祭坛、Boss 门和神器材料掉落视觉。
6. 小地图程序化图层。
7. 地形材质混合。
8. POI 模块化拼装。
9. 神器程序化外观。
10. 经营世界装饰生成。

原因：前四项直接影响核心玩法可读性，后四项主要提升内容量和美术丰富度。

## 18. Debug 工具

必须提供调试开关：

- 显示生成 seed。
- 显示 biome mask。
- 显示 terrain material mask。
- 显示资源节点 variant id。
- 显示矿坑模块 id、品级、槽位和枯竭层级。
- 显示洞穴 id、房间链、祭坛状态和 Boss 触发源。
- 显示 POI 模块边界和关键路径。
- 显示地形改造覆盖层 footprint。
- 显示法阵半径和危险边界。
- 显示小地图图层来源。

这些工具能防止程序化内容“看起来随机，问题却找不到原因”。

## 19. 验收标准

- 同一 match seed 下，程序化美术结果可复现。
- 不同 seed 下，地图视觉和 POI 细节有变化，但玩法识别不变。
- 地形改造正式覆盖层只在服务端确认后生成。
- 剑轨、法阵、神器 VFX 不影响权威伤害和资源。
- 火种、神器、敌我、危险区在程序化装饰中仍保持最高可读性。
- 低配降级后仍能读资源、法术范围、地形改造和战略目标。
