# 万国余烬：王冠赛季 插值与预测同步系统

**版本**：V2.0 重构设计版

**适用范围**：Bevy 0.18 客户端表现层、30Hz 权威模拟、高帧渲染、网络快照、预测与纠偏

**最后更新**：2026-06-17

**文档定位**：本文件定义插值系统的独立实现。它承接《Bevy 0.18 架构实现》的 30Hz 权威模拟方案，并细化客户端如何把权威状态平滑显示出来。

---

## 1. 设计目标

插值系统解决的问题：

- 服务端 30Hz 模拟，但客户端画面可以 60/120/144 帧甚至无上限。
- 远端玩家和怪物不因网络抖动一跳一跳。
- 本地玩家操作响应要快，但权威结果仍由服务端决定。
- 剑轨、法术、脚步、披风、相机和 UI 跟随可视层，不跟着 30Hz 抖动。
- 纠偏要可控，不能把角色硬拽得像瞬移。

一句话：**权威层负责正确，表现层负责顺滑，插值系统负责两者之间的翻译。**

---

## 2. 分层原则

每个会移动且需要显示的对象拆成两层：

```
Authority Entity
  SimTransform
  Gameplay Components
  NetIdentity
  RenderProxy

Visual Entity
  Transform
  Mesh / Animation / VFX Anchors
  Presentation Components
```

| 层 | 更新频率 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| Authority Entity | 30Hz `FixedUpdate` | 权威位置、碰撞、命中、拾取、状态 | 不能直接拿来做高帧渲染 |
| Visual Entity | 渲染帧率 `Update/PostUpdate` | 插值位置、动画、VFX、相机跟随 | 不能产生权威伤害、资源、拾取 |

---

## 3. 对象分类

不同对象使用不同同步策略。

| 对象 | 策略 | 说明 |
| --- | --- | --- |
| 本地玩家 | 预测 + 服务端纠偏 + 可视平滑 | 手感优先 |
| 远端玩家 | 快照缓冲 + 插值 + 有限外推 | 平滑优先 |
| 队友 | 快照缓冲 + 插值，标记更及时 | 可读优先 |
| 怪物/Boss | 快照缓冲 + 插值，技能事件权威触发 | 动画可读 |
| 资源节点 | 状态快照，不连续插值 | 采集量和枯竭状态权威 |
| 矿坑模块 | 槽位状态快照，不连续插值 | 占槽、产出、危险和枯竭权威 |
| 掉落物 | 生成事件 + 落地插值 | 不预测拾取 |
| 火种/神器 | 低延迟插值 + 事件强提示 | 战略目标要及时 |
| 地形覆盖层 | 事件式同步，无连续插值 | 建成/受损/拆除是离散状态 |
| 法术弹道 | 权威事件 + 表现插值 | 命中以服务端为准 |

## 6. Bevy 调度

推荐新增表现层 SystemSet：

```rust
#[derive(SystemSet, Debug, Clone, PartialEq, Eq, Hash)]
pub enum PresentationSet {
    ReceiveSnapshots,
    PredictLocal,
    BuildInterpolationTargets,
    ApplyVisualTransforms,
    Animation,
    Vfx,
    Camera,
    UiMarkers,
}
```

调度顺序：

```
PreUpdate
  -> receive_network_packets
  -> sample_input

FixedUpdate 30Hz
  -> authority simulation
  -> local prediction step
  -> snapshot acknowledgement

Update
  -> push snapshots into buffers
  -> predict local visual target
  -> calculate remote interpolation target
  -> apply visual transforms
  -> animation blend
  -> VFX follow
  -> camera follow

PostUpdate
  -> UI markers
  -> minimap
  -> nameplates
```

## 7. 远端实体插值

远端实体永远不按最新快照直接画。它们画“稍微过去一点”的时间点。

```
server_now_tick = estimated from snapshot stream
render_tick = server_now_tick - remote_delay_ticks
```

流程：

1. 收到快照，按 tick 插入 `SnapshotBuffer`。
2. 删除太旧帧，保留最近 0.5-1.0 秒。
3. 每帧计算 `render_tick_float`。
4. 找到前后两帧 `a` 和 `b`。
5. 位置 `lerp(a.pos, b.pos, alpha)`。
6. 旋转 `slerp(a.rot, b.rot, alpha)`。
7. 缩放通常不插值，除非是表现对象。

伪代码：

```rust
fn interpolate_remote(buffer: &SnapshotBuffer, render_tick: f32) -> Option<Transform> {
    let (a, b) = find_surrounding_frames(buffer, render_tick)?;
    let alpha = ((render_tick - a.tick as f32) / (b.tick - a.tick) as f32).clamp(0.0, 1.0);

    Some(Transform {
        translation: a.transform.translation.lerp(b.transform.translation, alpha),
        rotation: a.transform.rotation.slerp(b.transform.rotation, alpha),
        scale: a.transform.scale,
    })
}
```

## 8. 外推规则

外推只用于短暂丢包，不用于长期猜测。

允许：

- 快照缺失 1-3 tick 时，用上一帧速度短外推。
- 外推速度受最大移动速度限制。
- 外推期间降低脚步和剑轨强度，避免假动作太真。

禁止：

- 外推拾取火种/神器。
- 外推命中、死亡、开箱成功、地形建成。
- 外推超过 `max_extrapolation_ticks`。

外推失败后：

- 角色可短暂保持最后位置。
- 或用 0.1-0.2s 平滑拉到新快照。
- 如果距离过大，直接 snap 并播放失衡表现。

## 9. 本地玩家预测

本地玩家不能等服务端回包才动，否则手感会糟。移动和起手动画允许预测。

可预测：

- 移动。
- 疾跑蓄势。
- 闪避起手。
- 普通攻击起手动画。
- 采集动作起手。
- 法术瞄准预览。

不可最终预测：

- 实际伤害。
- 完美招架成功。
- 拾取火种/神器成功。
- 宝箱开出什么。
- 地形改造成功。
- 神器激活成功。
- 资源扣除和公开赛计分。

流程：

```
InputFrame(seq, tick, movement, buttons, look)
  -> local prediction applies movement immediately
  -> send input to server
  -> server confirms authoritative tick
  -> client drops confirmed inputs
  -> compare predicted state with server state
  -> replay unconfirmed inputs if needed
```

## 10. 纠偏系统

纠偏分三档：

| 误差 | 处理 | 视觉 |
| --- | --- | --- |
| `<= small_error_m` | 几帧内轻微平滑 | 玩家几乎无感 |
| `small_error_m` 到 `snap_error_m` | 0.1s 内加速修正 | 脚步加速或身体微倾 |
| `> snap_error_m` | 直接权威位置 | 播放失衡、被拉回或卡碰撞修正表现 |

伪代码：

```rust
fn reconcile(predicted: Vec3, authoritative: Vec3, config: &InterpolationConfig) -> Correction {
    let delta = authoritative - predicted;
    let error = delta.length();

    if error <= config.small_error_m {
        Correction::Smooth { delta, seconds: 0.06 }
    } else if error <= config.snap_error_m {
        Correction::Smooth { delta, seconds: config.smooth_correction_seconds }
    } else {
        Correction::Snap { target: authoritative }
    }
}
```

旋转纠偏：

- 小角度用 `slerp`。
- 大于 `rotation_snap_degrees` 时直接同步方向。
- 相机 yaw 不应被服务器硬拉，服务器只纠正角色身体朝向。

## 11. 动画与插值

动画读权威状态，但混合按渲染帧率。

| 数据 | 来源 | 更新 |
| --- | --- | --- |
| 位置 | 插值/预测 visual transform | 每渲染帧 |
| 移动速度 | visual delta 或权威 velocity | 每渲染帧 |
| 动作状态 | 快照 `animation_tag` / 本地预测 | 状态变化时 |
| 攻击有效帧 | 服务端权威事件 | Fixed tick |
| 剑轨 | visual bone socket | 每渲染帧 |
| 脚步 | visual speed + 地形材质 | 每渲染帧 |

攻击动画处理：

- 本地按键后立刻播放起手。
- 服务端拒绝时进入短取消/收势动画。
- 服务端确认命中时播放命中反馈。
- 远端攻击按权威事件播放，不用客户端猜测有效帧。

## 12. 相机与插值

相机跟随 visual entity，不跟随 authority entity。

规则：

- 鼠标视角每帧响应。
- 第三人称相机跟随插值后 pivot。
- 近战锁定或软锁只影响相机目标，不改权威朝向。
- 纠偏时相机不要完全跟着 snap，可在 0.05-0.12s 内过渡，减少眩晕。
- 第一人称手臂使用本地预测姿态，服务端纠偏只影响根位置。

---

## 13. 火种、神器和掉落物

战略目标需要比普通角色更及时。

### 13.1 王权火种

- 掉落事件必须立即显示。
- 位置可用 1-2 tick 插值延迟。
- 拾取必须等服务端确认。
- 如果本地预测拾取失败，播放“火种被拉回/抢先拾取”的短反馈。

### 13.2 全局唯一神器

- 现世、拾取、激活、掉落、封印使用权威事件。
- 持有者移动可插值。
- 神器 VFX 跟随 visual carrier。
- 神器能力范围以服务端快照为准，客户端预览只能作为提示。

### 13.3 普通掉落物

- 生成时可播放抛物线表现。
- 实际可拾取位置以服务端落点为准。
- 客户端不预测掉落归属。

## 14. 地形覆盖层

地形覆盖层不做连续运动插值。它是事件式状态：

```
Preview -> Server Approved -> Building -> Active -> Damaged -> Broken/Removed
```

规则：

- 客户端预览不参与碰撞。
- 服务端确认后生成正式实体。
- 建造读条可本地显示，但成功以服务端为准。
- 结构受损使用耐久快照驱动裂纹材质。
- 拆除/破坏用权威事件触发破碎 VFX。

---

## 15. 法术弹道

法术分两类：

| 类型 | 同步策略 |
| --- | --- |
| 读条/范围法术 | 预览本地显示，释放和命中权威确认 |
| 慢速弹道 | 服务端生成弹道实体，客户端插值显示 |
| 快速冲击 | 用权威命中事件播放表现，不模拟长弹道 |
| 持续区域 | 区域实体按状态快照同步 |

法术 VFX 可以提前播放前摇，但伤害数字、控制状态和资源扣除必须等权威消息。

| --- | --- |
| 30Hz 模拟 + 144Hz 渲染 | 本地移动不抖，远端移动平滑 |

| 火种拾取竞争 | 只有服务端确认者拿到火种 |
| 地形建造失败 | 预览消失，不留下碰撞 |

## 18. MVP 实现顺序

1. 实现 `SimTransform` 与 `RenderProxy`。
2. 本地单机：FixedUpdate 更新 authority，Update 插值 visual。
3. 加入远端 `SnapshotBuffer` 和插值。
4. 加入短外推和超时保持。
5. 加入本地移动预测与服务端确认。
6. 加入三档纠偏。
7. 接入动画、剑轨、相机。
8. 接入火种、神器、掉落物和地形覆盖层的特殊规则。
9. 做 debug overlay。

## 19. 验收标准

- 服务端 30Hz 时，客户端 60/120/144 帧渲染不出现位置台阶感。
- 本地玩家鼠标视角和移动响应不等待服务端回包。
- 远端玩家在轻微丢包下不明显跳动。
- 本地预测错误能被服务端纠正，并且不会产生假伤害或假拾取。
- 火种、神器、地形改造等关键结果始终由权威事件决定。
- 插值系统不写资源、生命、神器、公开赛计分等权威数据。
