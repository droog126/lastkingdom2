## 1. V1 → V2 差距速览

| V2 模块（来自《技术实现 MVP》§2） | V1 现状 | 关键缺口 |
| --- | --- | --- |
| MatchService（单局生命周期） | `core::sim::advance_demo_tick` 简版 | 缺 MatchPhase 状态机（灰烬开局 / 荒野竞逐 / 王权显形 / 终局收束）+ 阶段切换事件 |
| ProtectionService（保护期） | 无 | 缺开局 5min 全局保护 + 中途加入 5min 个人保护 |
| WorldGenService（肉鸽地形） | `world::WorldGenerator` 出种子 | 需同 seed 可复现 + 资源/POI/路线每局变 |
| POIService（背景建筑） | 无 | 需倒塌哨塔 / 旧集市 / 月纹小祠 / 灵井 / 旧王巢穴 |
| LootContainerService（宝箱） | 无 | 需普通补给箱 / 矿工铁匣 / 遗迹秘库 / 火种灰瓮 |
| EncounterService（怪物） | `monster::MonsterEcosystem` 有 | V2 需分类：小怪 / 守卫 / 精英 / Boss；守资源、守宝箱 |
| ResourcePoolService（资源池） | `resource::GlobalResourcePool` 有 | V2 需扩到 Wood / Food / Apple / Soul / 灵质 / 符文石 / 星砂 / 建国权 |
| MiningSiteService（矿坑） | 无 | 缺"矿坑模块"系统（露天 / 裂隙 / 灵脉 / 灾变）+ 槽位 + 爆率 + 枯竭 + 噪声半径 |
| CaveRogueService（肉鸽洞穴） | `scenario` 是状态机剧本 | V2 需 5-10min 短副本式房间链 + 奇遇/召唤 Boss + 神器材料 |
| EquipmentService（装备槽） | `pvp::WeaponStats` 单一武器 | 需 7 槽（主手/副手/身体/披肩/背部/法术焦点/临时遗物）+ 5 品质 + 耐久/维修 |
| StatService（数值聚合） | `pvp::CombatState` 有命中/硬直 | 需耐力 / 稳定 / 暴露 / 负重 / 维修等可读可配 |
| TerrainEditService（覆盖层） | `world::terrain` 可挖 | 缺挖沟 / 筑墙 / 架桥 / 修路 / 刻符 / 阵眼 / 预算 / 禁区 |
| SovereignSparkService（王权火种） | **没有** | 全新：实体、持有、死亡掉落、回流、建国消耗 |
| NationService（国家） | `nation::NationRegistry` 完整 | V1 用灵魂买旗 + 升级人口 → V2 改"火种建国" + 单局临时 + 回流 |
| CombatService（战斗进阶） | `pvp::*` 基础 | 需身法 / 简式剑术 / 月影剑 / 王庭剑 / 6 派法术（星火/霜纹/风歌/根须/...） |
| ArcanaRouteService（秘剑/法术/秘仪） | 无 | 局内解锁路线，3-5 条主路线 |
| UniqueArtifactService（全局唯一神器） | 无 | 每局 1-3 件，灰烬王冠 / 月下无鞘 / 星井法典 / 无归战旗 / 黑日残核 |
| EventService（肉鸽事件） | `scenario` 走剧本 | 需 灰烬开局 / 荒野竞逐 / 王权显形 / 终局收束 + 局部 PVP / 全局 PVP |
| RankingService（公开赛积分） | 无 | 排名 → 治理权更替 |
| CrownWorldService（经营世界） | 无 | 偏皮卡堂式社交经营：家具 / 皮肤 / 活动 / 治理权 |

## 4. 工程约束（必读，来自 V2 各分册）

- 玩法系统必须拆为 Bevy Plugin，不允许长期堆在 `main.rs`。
- 权威模拟在 `FixedUpdate`，表现 / 镜头 / UI / VFX 在 `Update` / `PostUpdate`。
- 跨系统通信优先 `Message` / `MessageReader` / `MessageWriter`。
- 客户端 `State` 可用 Bevy `States`；专服多房间**不能**用全局 App State 表示对局阶段。
- 表格包数值必须通过配置加载进 `GameTables`，系统**不得**硬编码核心数值。
- 装备 / 数值 / 神器 / 资源池 / 公开赛计分必须有服务端权威校验。
- 渲染 / 人物动画 / UI 系统**只**消费 Snapshot / PresentationState，**不能**直接写权威玩法组件。
- 地形改造必须用服务端确认的覆盖层实体，客户端预览不参与权威碰撞。

## 7. 风险与红线

- **不要碰 `compt` 版本**（V1 锁 `>=1.9, <1.10`，broccoli 0.6 不兼容 1.10）。
- **不要重新命名 crate**（`lk2-core` / `lk2-client` / `lk2-server` 是 lightyear 0.26 协议一致性需要的）。
- **不要把"王权火种"硬编码到旧 nation 路径**。要在 V2 nation 上另起一层 `SovereignSpark`，旧 nation 表作辅助。
- **不要动 lightyear 协议结构体**——会影响已连的客户端。
- **不要在 HUD / 渲染 / 动画里写权威伤害 / 资源 / 火种**。所有写权威状态走 `MessageWriter` → `FixedUpdate` 消费。
- **agent 视角**：本轮 quick win 全在 `lk2-core` 服务端权威层；不动 `lk2-client` 渲染管线（避免 1080 轮迭代的视觉基线回归）。下一轮再加客户端集成。
