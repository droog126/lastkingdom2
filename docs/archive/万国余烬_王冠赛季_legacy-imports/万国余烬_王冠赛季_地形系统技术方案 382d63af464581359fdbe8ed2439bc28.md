# 万国余烬：王冠赛季 地形系统技术方案

**版本**：V2.0 重构设计版

**适用范围**：世界生成、有限地形改造、地形覆盖层、碰撞/导航、同步、渲染、验收

**文档定位**：本文件定义地形系统技术实现。资源和改造数值以《表格包》为准，美术颜色以《美术风格与色彩规范》为准。地图高度、chunk、材质 mask、道路、河流、资源撒点和装饰加料见《地形高度与地表加料技术方案》。矿坑、采矿槽、爆率和采矿资源池见《矿坑与采矿模块技术方案》。肉鸽洞穴、房间链、Boss 召唤和神器材料见《肉鸽洞穴与神器材料技术方案》。可破坏地形、坑洞逃生、攀爬、填沟和自动脱困细节见《可破坏地形与坑洞逃生技术方案》。护城河、挖沟引水、水闸、涉水和排水规则见《交互液体与护城河技术方案》。

## 1. 地形系统目标

地形系统要保留“玩家能改变战场”的爽点，同时防止无限沙盒破坏对战。

目标：

- 玩家可以挖沟、筑墙、架桥、修路、刻符文槽、布阵眼、拆除和修复。
- 玩家不能无限挖地洞、无限造高墙、封死遗迹、删除 Boss 入口或堵出生点。
- 玩家不能制造无逃生路径的永久坑；所有坑洞必须能走出、翻越、攀爬、搭桥、填沟、队友救援或触发受限自动脱困。
- 玩家可以挖沟引水形成护城河，但水体采用受限格子水量和水源输出，不允许无限复制水或淹没关键路径。
- 所有地形变化都有材料、预算、时间、噪声和可破坏性。
- 服务端权威校验，客户端只做预览和表现。

核心方案：**静态基础地形 + 可编辑覆盖层 + 关键路径保护 + 预算限制**。

## 2. 地形分层

| 层 | 内容 | 是否可改 | 实现 |
| --- | --- | --- | --- |
| Base Terrain | 原始地图高度、材质、碰撞、导航 | 不直接改 | chunk mesh / heightfield |
| Biome Layer | 草地、岩地、湿地、遗迹、王座区 | 不直接改 | 生成时决定 |
| Resource Layer | 树、石料露头、灵脉、星砂、宝箱 | 可采集/破坏 | 独立实体 |
| Mining Module Layer | 露天矿坑、裂隙洞穴、灵脉矿井、灾变矿潮 | 可占槽采集/局部可改造 | 模块化实体 |
| Cave Module Layer | 洞穴入口、房间链入口、祭坛入口、Boss 门 | 可探索/不可自由改形 | 模块化实体 |
| POI Layer | 哨塔、旧集市、灵井、遗迹、王巢 | 局部可破坏 | 模块化实体 |
| Edit Overlay | 沟、墙、桥、路、符文槽、阵眼 | 可改 | 覆盖层实体 |
| Water Overlay | 水源、沟渠、护城河、水闸、湿泥/浅水/深水 | 可交互但受限 | 低分辨率水体格子 |
| Protection Layer | 出生点、主入口、关键路径、王座 | 不可封死 | 服务端校验体 |
| Nav Overlay | 改造后的通行修正 | 系统更新 | 增量更新 |

## 3. 地图生成

地图生成只决定基础世界和肉鸽路线，不生成玩家改造。

生成流程：

```
Seed
  -> Biome Layout
  -> Height / Terrain Material
  -> POI Placement
  -> Resource Node Placement
  -> Mining Site Placement
  -> Cave Entrance Placement
  -> Route Graph
  -> Protection Volumes
  -> Spawn Zones
  -> Event Anchors
```

MVP 地图不需要真无限世界，推荐中型固定尺寸 + seed 重排。

| 模块 | 规则 |
| --- | --- |
| Biome Layout | 5 个区域主题混合，避免单色地图 |
| POI Placement | 每条主路线至少 1 个 POI 锚点 |
| Resource Placement | 基础资源外圈多，地表露头低产，真正高产矿物进入矿坑模块 |
| Route Graph | 保证至少 3 条战略路线 |
| Protection Volumes | 出生点、遗迹主路、王座入口、Boss 门口 |
| Event Anchors | 火种、神器、矿潮、洞穴显影、夜陨、商队路线 |

## 3.1 矿坑不是自由挖洞

矿坑属于模块化地形实体，不属于玩家实时挖出的 Base Terrain 变形。服务端生成矿坑入口、内部可通行空间、采矿槽、堆料点和出口保护路径；玩家只能围绕它加固、修路、架桥、布防或破坏可破坏层。

禁止把矿坑实现成任意墙面可挖。采矿产出由 `MiningSiteModule` 的资源池和采矿槽控制，详细规则见《矿坑与采矿模块技术方案》。

## 4. 有限改造类型

| 改造 | 用途 | 限制 | 资源 |
| --- | --- | --- | --- |
| 挖沟 | 减速、阻挡推车、制造掩体 | 最大深度、不能连成永久地下城 | 石料/工具耐久 |
| 筑木墙 | 快速防御、临时围挡 | 高度低、易燃、可拆 | 木材/纤维 |
| 筑石墙 | 守点、防线 | 慢、重、预算高 | 石料/铁 |
| 架桥 | 跨沟、跨浅水、运输路线 | 长度限制、可破坏 | 木材/纤维/铁 |
| 挖沟引水 | 制造护城河、导水、阻推车 | 需连接水源，水量有限，不能淹没关键路径 | 工具耐久/水源输出 |
| 水闸/坝 | 控水、蓄水、排水 | 需读条，可破坏，输出有限 | 木材/石料/铁 |
| 修路 | 提升疾跑和推车效率 | 只能贴地，不能变成墙 | 石料/木材 |
| 符文槽 | 法阵导流、结界基座 | 需要工具，依赖灵质/符文 | 符文粉/符文石 |
| 阵眼基座 | 国家级法阵和终局仪式 | 需要权限和高暴露 | 石料/银/星砂 |
| 拆除 | 回收或破坏敌方结构 | 需要时间和声音暴露 | 工具耐久 |
| 修复 | 恢复己方结构 | 不能超过原始上限 | 对应材料 |

## 5. 改造预算

预算不是货币，是防止地图被刷满结构的系统限制。

| 预算 | 来源 | 作用 |
| --- | --- | --- |
| 个人预算 | 玩家入局固定 | 小沟、小墙、短桥、临时路 |
| 国家预算 | 建国后获得 | 防线、阵眼、符文塔周边 |
| 区域预算 | POI/王座/出生点限制 | 防止热点被完全封锁 |
| 时间预算 | 施工读条和噪声 | 防止瞬间造城 |
| 资源预算 | 材料和工具耐久 | 接入有限资源循环 |

每个 `TerrainEditEntity` 都占用预算，拆除后按规则返还部分预算和材料。

## 6. 关键路径保护

关键路径保护不是禁止所有建造，而是禁止“永久无解封死”。

保护对象：

- 出生区域出口。
- 遗迹主入口。
- Boss 巢穴入口。
- 王座区域至少两条通路。
- 国家核心最小可攻击路径。
- 商队主路线关键节点。
- 灵脉和阵眼最低交互空间。

校验方式：

```
TerrainEditIntent
  -> Check Protection Volume
  -> Check Route Graph Connectivity
  -> Check Min Passage Width
  -> Check Max Height / Depth
  -> Check Destructible Access
  -> Approve or Reject
```

如果改造会让关键路径只剩一条且无法破坏，拒绝。如果只是变难、变慢、需要破坏，则允许。

## 7. 服务端权威流程

```
Client Preview
  -> TerrainEditIntentMsg
  -> Server Validate
      -> material
      -> budget
      -> tool
      -> distance
      -> permission
      -> protection volume
      -> route connectivity
  -> TerrainEditCommittedMsg
  -> ResourceDeltaMsg
  -> Collision/Nav Update
  -> Snapshot Delta
```

客户端预览可以显示红绿黄，但最终结果必须以服务端为准。

## 9. 地形覆盖层实现

MVP 不做实时雕刻底层 mesh。所有改造都生成覆盖层实体。

| 改造 | 覆盖层形态 | 碰撞 |
| --- | --- | --- |
| 沟 | 下凹 mesh + 减速区域 | 简化碰撞盒或高度修正 |
| 木墙 | 模块化墙段 | 碰撞盒，可破坏 |
| 石墙 | 模块化墙段 | 碰撞盒，高耐久 |
| 桥 | 模块化桥板 | 可通行碰撞 |
| 道路 | 薄 mesh 或 decal | 速度区域，无阻挡 |
| 符文槽 | 薄 mesh + 发光线 | 无阻挡，法阵接口 |
| 阵眼 | 圆形平台 mesh | 可站立，可破坏 |

坑洞相关覆盖层不直接修改 Base Terrain。坑体使用 `PitVolume` 标记范围和逃生策略，具体规则见《可破坏地形与坑洞逃生技术方案》。

这样做的好处：

- 同步成本低。
- 回滚和审计容易。
- 不破坏原地图导航骨架。
- 可控地支持碰撞和可破坏。

## 10. 导航和移动修正

地形改造影响移动，但不必每次重建整张导航网。

| 地形 | 移动影响 |
| --- | --- |
| 道路 | 疾跑蓄势更稳定，推车阻力降低 |
| 泥地 | 加速慢，推车阻力高 |
| 浅水 | 减速，部分法术导流 |
| 沟 | 小跳或绕行，推车无法直接通过 |
| 木桥 | 可通行，破坏后断路 |
| 墙 | 阻挡，可破坏或绕行 |
| 符文槽 | 不阻挡，影响法术和阵眼 |

AI 和怪物使用简化导航：

- 普通小怪避开新墙和深沟。
- Boss 区域有固定战斗场地，不允许玩家封死。
- 护送路线在被堵时触发绕路或停滞事件。

## 11. 地形与资源循环

地形改造必须消耗有限资源，并能部分回流。

| 行为 | 资源流 |
| --- | --- |
| 筑墙 | 木/石/铁离开资源池，进入结构实体 |
| 拆除己方结构 | 回收一部分材料 |
| 破坏敌方结构 | 掉落碎料，一部分回流 |
| 烧毁木墙 | 少量炭材回流，大部分损失 |
| 阵眼失败 | 部分灵质/星砂散落 |
| 符文槽过载 | 符文粉损失，符文石低比例回收 |

所有变化发 `ResourceDeltaMsg` 并写审计。

## 12. 地形渲染

渲染层必须和碰撞状态一致。

规则：

- 客户端收到 `TerrainEditCommittedMsg` 后生成正式覆盖层。
- 预览层使用半透明材质，不参与权威碰撞。
- 受损结构切换裂纹材质或破损 mesh。
- 阵眼进度使用圆环刻度。
- 符文槽按插入资源色发光。
- 关键路径冲突预览使用敌意红。

颜色以《美术风格与色彩规范》为准。

## 13. 地形 UI

地形 UI 需要显示：

- 当前模式。
- 材料成本。
- 预算剩余。
- 施工时间。
- 噪声半径。
- 是否需要国家权限。
- 失败原因。

失败原因必须具体：

- 材料不足。
- 个人预算不足。
- 国家预算不足。
- 距离太远。
- 坡度过大。
- 高度超限。
- 深度超限。
- 关键路径不可封锁。
- 当前阶段禁止。

## 14. 网络同步

同步的是地形编辑事件，不是全地图 mesh。

| 数据 | 同步方式 |
| --- | --- |
| 新建改造 | `TerrainEditCommittedMsg` + transform + edit_type |
| 受损 | durability delta |
| 拆除 | removed/recycled message |
| 修复 | durability delta + resource cost |
| 阵眼进度 | progress snapshot |
| 道路速度区 | area effect snapshot |

客户端加入中途：

1. 接收基础地图 seed。
2. 接收当前所有有效 `TerrainEditEntity` 快照。
3. 本地重建覆盖层。
4. 后续只收增量。

## 15. 反滥用规则

- 禁止在出生点出口一定范围内建阻挡。
- 禁止把玩家完全封闭在不可破坏结构中。
- 禁止制造没有斜坡、翻越边、攀爬点、搭桥/填沟空间或救援方式的封闭坑。
- 禁止地下连续封闭超过安全时间。
- 禁止堆叠墙段形成超高墙。
- 禁止用道路/桥悬空构造无碰撞漏洞。
- 禁止把王权火种或神器丢进不可达地形。
- 断线玩家周围不能被瞬间封死。

服务端每次改造都校验，定期扫描热点区域。

## 16. MVP 范围

首发实现：

- 地形 chunk 和 biome 生成。
- 静态 POI 和资源点。
- 木墙、石墙、短桥、道路、浅沟、符文槽、阵眼基座。

- 玩家自定义建筑蓝图。
- 复杂地下城挖掘。

## 17. 验收标准

- 玩家能明显改变局部战场路线和攻防节奏。
- 玩家不能封死出生点、王座、Boss、遗迹主入口。
- 地形改造会消耗资源、占预算、产生施工时间。
- 拆除和破坏能回流部分资源。
- 客户端预览和服务端确认状态一致。
- 中途加入玩家能看到当前地形改造。
- 地形系统不允许客户端直接创建权威结构。
- 玩家掉入坑洞后必须存在明确逃生方式或受限自动脱困。
