# 万国余烬：王冠赛季 人物设计与角色技术方案

**版本**：V2.0 重构设计版

**适用范围**：人物美术、角色轮廓、装备槽、动画状态、身份识别、Bevy 角色实现

**最后更新**：2026-06-17

**文档定位**：本文件定义角色如何设计和实现。数值以《表格包》为准，渲染材质以《渲染技术方案》和《美术风格与色彩规范》为准。

## 1. 人物设计目标

角色要承担四个功能：

- **身份识别**：敌我、队友、国家、保护期、倒地、火种/神器携带者。
- **战斗读招**：轻击、突刺、重击、招架、闪避、吟唱、打断都要可读。
- **负重表达**：轻装、中载、重载、超载、大件搬运要从姿态上看出来。
- **奇幻气质**：优雅剑术、法术环、符文、王权秘仪，而不是粗糙兵器堆砌。

人物风格：比例略写实，动作优雅，服装层次清楚，轮廓干净。不要做成厚重盔甲互撞，也不要做成所有人都发光的页游效果。

---

## 2. 角色基础模型

MVP 推荐先做一个统一骨架，多个体型只改外观比例，不改核心碰撞。

| 项目 | 规则 |
| --- | --- |
| 身高 | 统一 gameplay capsule，高低差只做视觉 |
| 体型 | 轻、中、重三种轮廓预设 |
| 骨架 | 人形通用骨架，支持双手持物、单手剑、盾、法器、大件搬运 |
| 碰撞 | 胶囊体为主，装备不扩大受击盒 |
| 视角 | 第一人称手臂和第三人称全身共享装备状态 |
| 皮肤 | 经营皮肤只能改材质和装饰，不改碰撞和战斗读招 |

### 2.1 比例规格

人物比例采用 **7.5 头身的半写实英雄比例**。它比真实普通人更挺拔，但不夸张到动作像超英。优点是剑术姿态清楚、服装层次够用、第三人称远景也能读轮廓。

| 项目 | 推荐规格 | 说明 |
| --- | --- | --- |
| 视觉身高 | 1.76-1.84m | 体型差异只影响外观，不影响战斗判定 |
| 标准头高 | 0.235-0.245m | 约 7.5 头身 |
| 肩宽 | 2.1-2.35 头宽 | 轻装窄，王庭护卫略宽 |
| 臂长 | 指尖到大腿中段 | 保证剑、盾、法器动作自然 |
| 腿长 | 全身 51%-54% | 让疾跑、闪步和剑术步伐好看 |
| 手部 | 视觉可放大 5%-8% | 第一/第三人称读工具和剑势 |
| 脚部 | 视觉可放大 3%-5% | 强化步法、疾跑蓄势和急停 |

### 2.2 碰撞与相机规格

玩法判定统一，外观不带来优势。

| 项目 | 推荐规格 | 说明 |
| --- | --- | --- |
| 胶囊高度 | 1.78m | 服务端权威碰撞 |
| 胶囊半径 | 0.34m | 不随皮肤和装备变大变小 |
| 眼高 | 1.58m | 第一人称相机基准 |
| 第三人称 pivot | 1.35-1.45m | 约胸口到肩线之间 |
| 第三人称距离 | 3.2-4.2m | 战斗默认，狭窄处自动收近 |
| 肩偏移 | 0.35-0.55m | 可左右切肩 |
| 近战判定 | 胶囊 + 武器扫掠 | 不用细胳膊做受击盒 |
| 头部判定 | MVP 不做独立爆头类收益 | 避免视角和体型争议 |

### 2.3 体型预设

体型只改变轮廓，不改变数值。

| 预设 | 轮廓 | 用途 |
| --- | --- | --- |
| 轻盈型 | 窄肩、短披肩、腿部线条清楚 | 适合月影剑、风歌剑、侦查和追击 |
| 标准型 | 最均衡，装备挂点清楚 | 默认玩家和多数 NPC |
| 稳重型 | 肩背更宽，手臂护具更明显 | 适合王庭剑、护卫、搬运者 |

禁止做“瘦小体型更难打”“高大体型视野更高”这类战斗差异。公开赛只认统一胶囊。

## 3. 角色轮廓语言

| 状态 | 轮廓要求 | 玩家应读到的信息 |
| --- | --- | --- |
| 空手/初始 | 轮廓简洁，布衣和小包 | 早期开局、低威胁 |
| 轻装剑士 | 窄肩、短披肩、剑挂腰侧 | 高机动、追击/侧切 |
| 王庭护卫 | 肩部和前臂更稳定，盾或重剑明显 | 格挡、守点、抗线 |
| 法术研习者 | 腰侧法术环、手腕符带、轻披肩 | 可能吟唱和控制 |
| 重载搬运者 | 背部大件、双手占用或肩扛 | 高价值运输、弱战斗 |
| 火种携带者 | 背后或手中余烬核心 | 战略目标 |
| 神器携带者 | 黑金外圈、专属副色、姿态负担 | 全局最高争夺目标 |
| 倒地玩家 | 低位姿态、救援轮廓 | 可救援/可处决风险 |

## 4. 装备槽设计

装备槽要服务可读性和技术实现。

| 槽位 | 可见挂点 | 玩法 |
| --- | --- | --- |
| `main_hand` | 右手/腰侧 | 剑具、工具、法器 |
| `off_hand` | 左手/背侧 | 盾、法器、副手工具 |
| `body` | 躯干 | 衣甲、防护、负重 |
| `cloak` | 肩背 | 披肩、结界披肩、身份装饰 |
| `back` | 背部 | 背篓、大件、火种支架 |
| `focus` | 腰侧/手腕 | 法术环、调灵叉、灵视测镜 |
| `relic` | 双手/背负特殊位 | 全局唯一神器 |

技术规则：

- 装备外观跟随 `EquipmentInstance` 和 `Loadout`。
- UI 不能直接改模型，只发送 `EquipIntentMsg`。
- 服务端确认穿戴后，客户端更新可见挂点。
- 经营皮肤不能隐藏 `relic`、`back`、`focus` 的核心轮廓。

## 5. 动画状态机

角色动画分为基础层、上身层、携带层、状态层。

```
Base Locomotion
  -> Idle / Walk / Jog / SprintRamp / SprintFull / Stop / Turn
Upper Body
  -> Gather / LightSlash / Thrust / HeavySlash / Guard / Parry / Cast / UseItem
Carry Layer
  -> Free / Backpack / HandCarry / ShoulderCarry / TwoPlayerCarry / RelicCarry
Status Layer
  -> Protected / Downed / Staggered / Rooted / ArtifactBurden
```

| 层 | 作用 |
| --- | --- |
| 基础移动层 | 表达速度、方向、疾跑蓄势和急停 |
| 上身动作层 | 表达攻击、招架、采集、施法 |
| 携带层 | 表达背包、大件、火种、神器 |
| 状态层 | 表达受击硬直、倒地、保护、束缚 |

## 6. 疾跑蓄势表现

用户提到的“疾跑需要达到一定时间才能满速度”必须进人物表现。

| 阶段 | 动画 | 视觉反馈 |
| --- | --- | --- |
| 起跑 0-0.4s | 身体前倾，步频提升 | 无风线或极弱尘线 |
| 蓄势 0.4-1.4s | 步幅变大，肩部稳定 | 脚边短尘线 |
| 满势 1.4s 以后 | 稳定高速姿态 | 流派相关轻微尾迹 |
| 受击中断 | 身体失衡 | 尾迹断开，短硬直 |
| 重载蓄势 | 起跑慢，重心低 | 尘线重但无轻盈风线 |
| 超载 | 只能走/慢跑 | 不出现疾跑姿态 |

疾跑视觉只表达状态，不提供额外玩法结果；真实速度由 `MovementPlugin` 和服务端权威 `StatBlock` 决定。

## 7. 采集与携带动作

采集不是原地读条，应有工具、弱点和声音暴露。

| 行为 | 动画要求 | 风险表达 |
| --- | --- | --- |
| 砍树 | 双手挥斧，命中树纹 | 木屑、声音圈提示 |
| 采矿 | 矿镐重击，命中裂线 | 火花、回声、身体硬直 |
| 采灵质 | 调灵叉稳定，手部青光 | 脉冲环、可被打断 |
| 开宝箱 | 蹲姿/半跪，手部操作 | 开箱圈、声音、背后脆弱 |
| 推车 | 双手占用，转向慢 | 车轮声、路线暴露 |
| 肩扛大件 | 上身受限，不能完整招架 | 高价值目标轮廓 |
| 双人搬运 | 两人绑定节奏 | 任一人受击会打断 |

## 8. 剑术动作设计

剑术关键词：克制、清楚、优雅。

| 招式 | 姿态 | 可读点 |
| --- | --- | --- |
| 轻击 | 短弧、快收 | 方向明确，后摇短 |
| 突刺 | 身体压低、直线出剑 | 距离明确，可侧闪 |
| 重击 | 肩部蓄力、步伐明显 | 前摇足够，命中强 |
| 格挡 | 剑/盾在身体中心线 | 可看出防御方向 |
| 完美招架 | 瞬间收线、冷闪 | 成功反馈短促 |
| 闪步 | 侧身滑步，不是传送 | 有起步和落点 |
| 破阵 | 剑指地面或阵眼 | 只在结构互动时强化 |

每个动作必须有：

- `startup` 前摇。
- `active` 有效帧。
- `recovery` 收招。
- `cancel_window` 可取消窗口。
- `stamina_cost` 耐力消耗。

数值写在《表格包》，动画只读配置标签。

## 9. 法术动作设计

法术不是瞬发光污染。每个法术至少有手势、符文、目标提示。

| 学派 | 动作语言 | 读招方式 |
| --- | --- | --- |
| 星火术 | 手部聚点、向前推送 | 星点变亮，落点暖色圈 |
| 霜纹术 | 手指划纹、地面结霜 | 霜纹路径清晰 |
| 风歌术 | 旋身、袖摆和步法 | 绿青风线预告推力 |
| 根须术 | 手掌压地、藤纹扩散 | 地面根纹先出现 |
| 灵视术 | 手持测镜/手势扫描 | 青色环扫过，不遮屏 |
| 王权秘仪 | 双手举火/冠形手势 | 王冠金环和全局提示 |

法术动作可被打断时，动画必须给出打断点，不能让玩家觉得技能“凭空没了”。

## 10. 身份与阵营识别

视觉识别优先级：

1. 敌我描边。
2. 火种/神器携带。
3. 保护期/倒地/控制状态。
4. 国家纹章。
5. 装备与皮肤。

| 信息 | 表现 |
| --- | --- |
| 敌方 | 敌意红短描边或 UI 标记，不能长期全身红光 |
| 友方 | 友方绿细环、名称板 |
| 队友 | 蓝色内芯或队伍图标 |
| 国家成员 | 纹章布片、旗色边，但不能盖掉敌我 |
| 保护期 | 半透明圆盾，不可攻击状态 |
| 倒地 | 救援图标和低姿态 |
| 火种 | 余烬拖痕 |
| 神器 | 黑金星冠轮廓 |

## 11. 怪物与 Boss 角色

怪物要优雅、可读、路线明确。

| 类型 | 骨架 | 技术重点 |
| --- | --- | --- |
| 灰烬游灵 | 简化漂浮骨架 | 透明度、短闪、受击显形 |
| 根须仆从 | 四足/根足 | 缠绕前摇、地面根纹 |
| 符文哨卫 | 小型人形/石甲 | 盾臂亮起后出手 |
| 洞窟空壳 | 弯背人形 | 听声转头，突袭前摇 |
| 灵脉鹿 | 四足轻盈 | 跳跃、脉冲、非血腥掉落 |
| 月下残影 | 人形剑士 | 教学招架和闪步 |
| 遗迹石像 | 大型人形 | 核心亮起、慢重击 |
| 旧王残影 | Boss 人形 | 破冠、分身、王权火种掉落 |

Boss 不靠巨大血条压迫，靠阶段、场地、读招和掉落风险形成事件。

## 12. Bevy 组件设计

```rust
#[derive(Component)]
pub struct CharacterVisualRoot;

#[derive(Component)]
pub struct EquipmentSocket {
    pub slot: EquipmentSlot,
}

#[derive(Component)]
pub struct AnimationStateTag {
    pub locomotion: LocomotionState,
    pub upper: UpperBodyState,
    pub carry: CarryVisualState,
    pub status: StatusVisualState,
}

#[derive(Component)]
pub struct ReadabilityMarker {
    pub marker_type: MarkerType,
    pub priority: u8,
}
```

数据流：

```
Server Snapshot
  -> PlayerState / Loadout / CarryState / ArtifactCarrier
  -> CharacterPresentationSystem
  -> AnimationStateTag + EquipmentSocket + ReadabilityMarker
  -> Render / UI / VFX
```

## 14. 经营皮肤限制

允许：

- 服装颜色、布料纹样、发型、脸部装饰。
- 非战斗场景的更亮装饰。
- 入场动作、社交动作、经营世界表情。

禁止：

- 改变碰撞体。
- 缩小角色轮廓。
- 隐藏火种、神器、大件、装备槽。
- 使用敌意红、火种橙白内核、神器黑金外圈伪装。
- 改变敌我、法术危险区、剑术读招颜色。

---

## 15. 验收标准

- 远处能判断轻装、重载、搬运、持火种、持神器。
- 近战五个基础动作在 1v1 和混战中可读。
- 疾跑蓄势、受击中断和负重惩罚有明确视觉反馈。
- 法术前摇、释放、残留三段清楚。
- 经营皮肤不会破坏公开赛公平性和可读性。
- 角色表现系统只读权威状态，不直接改玩法结果。

## 16. 实际操作模型

默认操作应以第三人称为主，第一人称用于采集、观察和精细交互。游戏不是纯锁定动作，也不是完全自由乱挥，而是 **相机方向 + 移动方向 + 当前姿态** 决定招式倾向。

### 16.1 默认键鼠映射

| 输入 | 动作 | 说明 |
| --- | --- | --- |
| WASD | 移动 | 相机相对移动 |
| 鼠标 | 视角 | 渲染帧率即时响应 |
| Shift | 疾跑蓄势 | 按住进入起跑、蓄势、满势 |
| Space | 闪避/越沟 | 受负重和耐力影响 |
| LMB | 主手轻击/工具使用 | 剑为轻击，工具为采集 |
| Hold LMB | 重击/强采 | 有明显前摇和耐力消耗 |
| RMB Tap | 招架尝试 | 短窗口，高风险高收益 |
| Hold RMB | 格挡/法术瞄准 | 持盾为格挡，持法器为瞄准 |
| Q | 当前法术 | 按住预览，松开发动 |
| E | 交互 | 拾取、开箱、上车、启动仪式 |
| F | 副手/法器功能 | 灵视、护牌、调灵 |
| R | 收起/切换当前手持 | 工具、剑、法器之间切换 |
| G | 丢弃/放下大件 | 火种和神器使用高风险确认 |
| M | 地图/战略图 | 国家指挥和路线 |
| B | 地形工具 | 有工具或权限时打开 |
| X | 第一/第三人称切换 | 狭窄采集和战斗可切换 |

### 16.2 剑术输入逻辑

| 条件 | 招式倾向 |
| --- | --- |
| 静止 + LMB | 标准横切 |
| 前进 + LMB | 突刺或推进斩 |
| 左/右移动 + LMB | 侧切 |
| 后退 + LMB | 后撤斩 |
| 疾跑满势 + LMB | 追击起手 |
| Hold LMB | 重击，前摇更明显 |
| RMB Tap 成功 | 完美招架，进入短反击窗口 |
| Hold RMB | 普通格挡，消耗耐力 |

剑术不做复杂搓招，重点是距离、方向、节奏和读招。

### 16.3 法术输入逻辑

| 操作 | 规则 |
| --- | --- |
| 按住 Q/数字键 | 显示法术预览、范围、消耗和可打断状态 |
| 松开 | 发动法术 |
| RMB | 取消或进入精确瞄准 |
| 移动中施法 | 小法术允许，仪式和大法术减速或定身 |
| 受击 | 按法术韧性判断是否打断 |

法术必须让对手看见前摇和范围。强控制和大范围法术不能瞬发。

### 16.4 携带与采集操作

| 状态 | 操作变化 |
| --- | --- |
| 背包正常 | 可战斗、可闪避、可疾跑 |
| 重载 | 疾跑蓄势变慢，闪避距离缩短 |
| 超载 | 不能疾跑，交互变慢 |
| 手持大件 | LMB/RMB 改为放置/推挤，不能完整剑术 |
| 肩扛大件 | 可慢走，可短跳，不能招架 |
| 推车 | WASD 控车，转向慢，倒车慢 |
| 双人搬运 | 两人移动方向取合成，任一人受击会打断 |

### 16.5 相机手感

- 第三人称默认不硬锁敌人，只提供软锁和目标提示。
- 按住格挡或法术瞄准时，相机稍微收紧并降低横向漂移。
- 疾跑满势时 FOV 可轻微扩大，但不影响命中判定。
- 近战受击只做短反馈，不大幅摇晃相机。
- 狭窄洞穴、宝箱、采灵质时可切第一人称提高操作精度。

## 17. 30Hz 模拟下的人物表现

人物动作不能直接每 33ms 跳一次。角色表现层按渲染帧率插值，权威层按 30Hz 结算。

| 内容 | 更新频率 | 说明 |
| --- | --- | --- |
| 权威位置 | 30Hz `FixedUpdate` | 服务端判定 |
| 可视位置 | 渲染帧率 `Update` | previous/current 插值 |
| 鼠标视角 | 渲染帧率 `PreUpdate/Update` | 保证不发木 |
| 动画混合 | 渲染帧率 | 用权威状态驱动，平滑混合 |
| 命中判定 | 30Hz + 扫掠 | 不依赖单帧视觉剑轨 |
| 剑轨/VFX | 渲染帧率 | 表现用，不产生权威伤害 |

本地玩家允许预测移动和起手动画，但伤害、拾取、开箱、地形改造和神器激活必须等服务端确认。
