# 万国余烬：王冠赛季 可破坏地形与坑洞逃生技术方案

**版本**：V2.0 重构设计版

**适用范围**：可破坏地形覆盖层、坑洞/沟壕、攀爬、填土、搭桥、救援、卡死检测、自动脱困

**最后更新**：2026-06-17

**文档定位**：本文件是《地形系统技术方案》的专项补充，专门定义“玩家掉进坑里怎么办”。本项目不做无限体素挖掘，而做可控的可破坏战术地形。

---

## 1. 核心结论

可破坏地形不是把地图挖没，而是 **不可破坏世界骨架 + 可破坏战术覆盖层 + 局部可破坏 POI**。

玩家可以：

- 挖浅沟。
- 破墙。
- 断桥。
- 拆阵眼。
- 打开 POI 侧门。
- 破坏敌方工事。
- 用法术或工具改变局部战场。

玩家不能：

- 挖无限深坑。
- 制造永久不可逃脱的坑。
- 封死出生点、王座、Boss、遗迹主入口。
- 把火种或神器丢进不可达区域。
- 把其他玩家永久困住。

---

## 2. 可破坏层级

| 层级 | 是否可破坏 | 示例 | 逃生要求 |
| --- | --- | --- | --- |
| 世界骨架 | 不可破坏 | 山体主轮廓、出生出口、王座主入口 | 不应形成坑 |
| 战术覆盖层 | 可破坏 | 木墙、石墙、桥、浅沟、路障、阵眼 | 必须有出坑路径或可制造路径 |
| POI 外层 | 局部可破坏 | 哨塔木板、旧集市棚架、遗迹侧门 | 不能封死主路线 |
| 危险坑/事件坑 | 临时可变 | 灾变裂隙、Boss 场地坑 | 必须有倒计时、跳出点或救援规则 |

---

## 3. 坑洞分类

| 类型 | 深度 | 逃生方式 | 是否允许 |
| --- | --- | --- | --- |
| 浅沟 | 0.4-0.8m | 直接走出或跳出 | 允许 |
| 战术沟 | 0.8-1.5m | 斜坡、跳跃、攀爬、搭桥 | 允许 |
| 深坑 | 1.5-2.5m | 必须有坡道、攀爬点或工具逃生 | 条件允许 |
| 封闭坑 | 任何深度 | 无出口、无攀爬、无搭建空间 | 禁止 |
| 事件裂隙 | 2m 以上 | 事件规则、传送/喷发/救援 | 只限事件，不能玩家自由制造 |

MVP 推荐玩家可制造的最大深度仍按《表格包》的 `trench_max_depth` 控制，默认 1.5m。超过 1.5m 的坑应来自事件或 POI，不来自普通玩家挖掘。

## 4. 出坑方式

玩家掉进坑里，系统按优先级提供这些方式。

### 4.1 走坡出坑

如果坑壁坡度低于可行走阈值，玩家直接走出。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `walkable_slope_max` | 42 度 | 低于此坡度可行走 |
| `mud_slope_penalty` | 20% | 泥地出坑更慢 |
| `heavy_load_slope_penalty` | 30% | 重载爬坡更慢 |

### 4.2 跳跃/翻越

如果坑边高度不高，玩家可以跳出或翻越。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `vault_height_max_light` | 1.2m | 轻装可翻越高度 |
| `vault_height_max_heavy` | 0.8m | 重载可翻越高度 |
| `vault_stamina_cost` | 18 STA | 翻越消耗 |
| `vault_interrupted_on_hit` | true | 受击打断 |

### 4.3 攀爬点

战术沟或深坑必须生成攀爬点。

攀爬点来源：

- 坑壁自然裂缝。
- 玩家放置绳索。
- 木板/石块形成的踏点。
- POI 固定梯段。
- 法术生成的根须/风阶。

规则：

- 攀爬期间不能攻击。
- 可被攻击打断。
- 重载攀爬更慢。
- 肩扛大件不能攀爬，必须放下大件。

### 4.4 搭桥

玩家可用木板、石块或桥包跨越坑。

要求：

- 需要材料。
- 需要放置空间。
- 需要服务端确认。
- 桥可被破坏。
- 手推车和商队需要桥宽满足通行宽度。

### 4.5 填土/填沟

玩家可消耗石料、木材、碎石填平局部坑。

规则：

- 只填覆盖层坑，不改 Base Terrain。
- 填沟会消耗材料，占用施工时间。
- 填平后生成道路/碎石覆盖层。
- 敌方可打断施工。

### 4.6 队友救援

队友可以从坑边放绳、搭桥或拉人。

救援规则：

- 需要短读条。
- 受击打断。
- 重载玩家救援时间更长。
- 持火种/神器时救援会有明显暴露提示。

### 4.7 自动脱困

自动脱困是最后兜底，不是常规移动能力。

触发条件：

- 玩家在封闭坑内无法到达任何可行走出口。
- 周围无可放置桥/填土空间。
- 玩家连续卡死超过阈值。
- 当前不是战斗中、不是持有火种/神器争夺状态，或使用脱困会强制掉落高价值物。

自动脱困结果：

- 将玩家移动到最近合法安全点。
- 消耗时间。
- 暴露位置。
- 如果携带王权火种或全局唯一神器，先掉落在原坑边合法点，再脱困。

## 5. 防困规则

服务端在地形改造时必须校验“困人风险”。

禁止：

- 生成完全垂直且无攀爬点的封闭坑。
- 用墙体把坑口完全封住。
- 在断线玩家、倒地玩家或保护期玩家周围瞬间封坑。
- 把火种、神器、Boss 掉落物放进不可达坑。
- 在关键路径上制造只能单方通行的坑。

允许：

- 让路线变慢。
- 让推车绕路。
- 让敌人需要搭桥或拆除。
- 制造短期战术陷阱。
- 在有反制工具的情况下制造防线。

## 6. Bevy 组件

```rust
pub struct PitVolume {
    pub pit_id: TerrainEditId,
    pub depth_m: f32,

pub struct EscapeAnchor {

pub struct StuckProbe {
    pub last_valid_position: Vec3,

pub struct ClimbState {
    pub anchor: Entity,
    pub progress: f32,
    pub interrupted: bool,
}
```

```rust
pub enum EscapePolicy {
    WalkOut,
    VaultAllowed,

    Rope,
```

## 8. 服务端校验流程

玩家挖坑：

```
TerrainEditIntent(DigPit)
  -> Check Max Depth
  -> Check Footprint
  -> Check Protection Volume
  -> Check Route Connectivity
  -> Check Escape Policy
  -> Generate Escape Anchors If Required
  -> Reject If Enclosed Without Escape
  -> Commit Pit Overlay
```

玩家掉坑：

```
Player enters PitVolume
  -> Query walkable slope
  -> Query vaultable ledge
  -> Query escape anchors
  -> Query buildable bridge/fill locations
  -> Update UI hints
  -> Start StuckProbe
```

玩家请求逃生：

```
EscapeAttempt
  -> Check stamina
  -> Check load/carry state
  -> Check combat interruption
  -> Check anchor/build location
  -> Apply time/read bar
  -> Commit movement or construction
```

## 9. 坑洞导航检测

服务端需要一个轻量可达性检测，不需要重建全图导航。

检测范围：

- 坑体 footprint。
- 周围 3-8m 环。
- 最近可行走地面。
- 最近攀爬点。
- 最近可放置桥/填土点。

判定：

```
reachable_exit_exists =
  walkable_slope_exists
  OR vaultable_ledge_exists
  OR escape_anchor_exists
  OR buildable_exit_exists
  OR ally_rescue_possible
```

如果 `reachable_exit_exists == false`，该坑不能提交，或必须自动生成至少一个 `EscapeAnchor`。

## 10. 负重与大件限制

掉坑后，负重会影响逃生。

| 状态 | 出坑影响 |
| --- | --- |
| 轻装 | 可跳、可翻、可快攀 |
| 中载 | 可翻较低边缘，攀爬变慢 |
| 重载 | 翻越高度降低，攀爬耗耐增加 |
| 超载 | 不能翻越，必须放下大件、搭桥或救援 |
| 手持大件 | 不能攀爬，需放下或队友接应 |
| 肩扛大件 | 不能翻越，能走坡 |
| 持火种 | 可逃生，但暴露提示更强 |
| 持神器 | 逃生速度降低，自动脱困前强制掉落 |

## 11. UI 提示

玩家掉坑后，UI 不应只显示“卡住了”，而应显示具体可行方式。

提示优先级：

1. `可沿斜坡走出`
2. `按 Space 翻越`
3. `按 E 攀爬`
4. `需要放下大件`
5. `可放置木桥`
6. `可填平沟壑`
7. `等待队友救援`
8. `自动脱困倒计时`

高风险提示：

- 持火种：`脱困会暴露你的位置`
- 持神器：`自动脱困会先掉落神器`
- 战斗中：`受击会打断攀爬/救援`
- 超载：`超载无法翻越，请放下大件`

## 12. 可破坏结构耐久

| 结构 | 耐久定位 | 破坏后 |
| --- | --- | --- |
| 木墙 | 低耐久，易拆 | 掉落少量木碎料 |
| 石墙 | 中高耐久 | 掉落碎石，形成低矮障碍 |
| 桥 | 中耐久 | 断桥，留下桥墩或木板 |
| 符文槽 | 低耐久但需工具/法术破坏 | 灵质散落或符粉损失 |
| 阵眼 | 高价值结构 | 触发全局/区域提示 |
| POI 外层 | 按模块耐久 | 打开侧路或掉落装饰碎片 |

破坏永远不能产生超过建造成本的资源回流。

## 13. 自动脱困反作弊

自动脱困不能变成逃跑技能。

限制：

- 近期受到玩家伤害时不能立即自动脱困。
- 正在携带火种或神器时不能无代价脱困。
- 自动脱困位置必须是最近合法点，不允许选择远处安全点。
- 自动脱困有明显音效/视觉提示。
- 自动脱困写审计日志。

推荐：

| 参数 | 默认 |
| --- | --- |
| `stuck_probe_time` | 6s |
| `auto_rescue_countdown` | 8s |
| `recent_combat_block` | 10s |
| `auto_rescue_reveal_radius` | 80m |

## 14. MVP 实现范围

首发实现：

- 浅沟和战术沟。
- 坑体 `PitVolume`。
- 斜坡走出。
- 低边翻越。
- 固定攀爬点。
- 木桥跨坑。
- 石料/碎石填沟。
- 卡死检测。
- 自动脱困兜底。
- 火种/神器不可达保护。

暂缓：

- 完整绳索物理。
- 任意墙面攀爬。
- 可挖大型地下洞穴。
- 水流灌坑。
- 复杂坍塌模拟。

---

## 15. 验收标准

- 玩家掉入普通浅沟后能直接走出或跳出。
- 玩家掉入战术沟后至少有一种逃生方式：攀爬、搭桥、填沟或救援。
- 服务端拒绝无出口封闭坑。
- 玩家不能把火种或神器丢进不可达坑。
- 自动脱困只在卡死时触发，不能作为战斗逃跑手段。
- 所有坑、桥、填沟和攀爬状态都由服务端确认。
