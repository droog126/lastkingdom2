## 1. 技术定位

《万国余烬：王冠赛季》不是纯沙盒，也不是纯竞技场。它的技术核心是 **服务端权威多人对战 + 数据驱动肉鸽局内系统 + 可控地形改造 + 强可读奇幻表现 + 经营世界轻量持久化**。

技术路线必须围绕四个目标收敛：

- **公平**：公开活动赛内所有战斗数值由局内生成，服务端权威校验。
- **可读**：剑术、法术、资源、神器、火种、敌我和地形危险必须在混战中一眼能读。
- **可审计**：资源池、火种、神器、公开赛积分和经营治理权必须有日志轨迹。
- **可扩展**：玩法系统拆成 Bevy Plugin，数值和资产走配置表，不把规则写死在表现层。

## 2. 技术栈建议

| 层级 | 方案 | 原因 |
| --- | --- | --- |
| 引擎 | Bevy 0.18 | ECS、插件化、Rust、适合服务端 Headless 与客户端共享玩法代码 |
| 渲染 | Bevy PBR + 自定义 Material/WGSL + 后处理分层 | 普通环境用 PBR，神器/法术/灵脉用专用材质 |
| UI | Bevy UI 为主，调试期可临时接 egui 类工具 | MVP 优先 ECS 一体化，避免 UI 与玩法状态割裂 |
| 网络 | 服务端权威，客户端发送 Intent，服务端广播 Snapshot | 防止客户端改资源、生命、神器、火种和公开赛积分 |
| 配置 | RON/JSON 表格 + 启动校验 | 和《表格包》保持一致，可赛季调参 |
| 资产 | glTF/GLB、PNG/WebP、WGSL、RON | 兼顾 DCC 管线、材质、动画和配置 |
| 数据持久化 | 局内内存状态 + 赛后落库 | 单局快，赛后排名和经营资产持久 |

## 3. 工程边界

| crate | 核心职责 | 不能做什么 |
| --- | --- | --- |
| `ember_shared` | ID、配置结构、协议、纯公式 | 不能依赖 Bevy 渲染和窗口 |
| `ember_game` | 玩法 ECS、权威模拟、资源/装备/地形/神器 | 不能直接读键鼠、不能生成 UI 皮肤 |
| `ember_client` | 渲染、输入、UI、镜头、VFX、音频、预测显示 | 不能直接产生权威资源或伤害结果 |
| `ember_server` | Headless 权威模拟、快照、审计、排名提交 | 不能依赖 GPU、窗口、客户端资产细节 |

专项文档对应关系：

| 专项 | 主要落地 crate | 事实边界 |
| --- | --- | --- |
| 渲染技术方案 | `ember_client`, 少量 `ember_game` 标记组件 | 怎么把玩法状态画出来 |
| 人物设计与角色技术方案 | `ember_game`, `ember_client` | 角色轮廓、装备槽、动画状态、身份识别 |
| UI 设计技术方案 | `ember_client`, `ember_shared` 协议 | 玩家如何读规则、下指令、看风险 |
| 地形系统技术方案 | `ember_game`, `ember_server`, `ember_client` | 地形如何生成、改造、同步、渲染 |

## 4. 总体系统图

```
Config Tables
  -> GameTables
  -> Server Authority FixedUpdate
      -> Intent Validation
      -> Movement / Combat / Resource / Terrain / Artifact
      -> Audit Log
      -> Snapshot
  -> Client Prediction + Presentation
      -> Render World
      -> Character Animation
      -> UI State
      -> VFX / Audio
```

所有关键玩法都按这个方向走：客户端发意图，服务端验证，服务端给结果，客户端表现。

## 5. 数据驱动原则

必须配置化：

- 资源池总量、节点产出、回流比例。
- 矿坑模块数量、采矿槽、爆率、枯竭、噪声和运输负重。
- 肉鸽洞穴数量、房间链、奇遇 Boss、召唤 Boss、神器材料和唤醒路线。
- 装备槽、装备重量、耐久、修理、掉落。
- 剑术招式、法术消耗、吟唱、打断窗口。
- 神器数量、冷却、负担、反制、封印收益。
- 地形改造预算、尺寸、禁区、材料成本。
- UI 图标、颜色、稀有度、提示优先级。
- 渲染分层、LOD 距离、VFX 上限和低配降级。
- 程序化美术 seed、材质 mask、资源节点变体、矿坑模块、POI 模块、剑轨/法阵参数和小地图图层。

禁止：

- 在 UI 代码里写伤害公式。
- 在渲染代码里改变权威状态。
- 在客户端预测里生成真实掉落。
- 在经营资产里挂公开赛战斗 modifier。

## 6. 性能目标

MVP 先按中型地图、60 人标准局设计。

| 项目 | 目标 |
| --- | --- |
| 客户端帧率 | 推荐配置 60 帧/秒，低配 30 帧/秒可玩 |
| 服务端模拟 | 30 Hz FixedUpdate |
| 单局玩家 | 40-60 人 |
| 可见角色 | 近处高细节 12-20 人，中远距降级 |
| 同屏 VFX | 高优先级不限，低优先级池化和裁剪 |
| 地形改造同步 | 事件增量同步，不整图同步 |
| UI 延迟 | 关键提示一帧内显示，结算可异步 |
| 资源审计 | 权威结果全部记录，表现事件可采样 |

## 7. 渲染方向

渲染目标不是炫技，而是 **低成本建立奇幻王权气质和 PVP 可读性**。

技术原则：

- 地形和建筑使用低饱和 PBR 材质。
- 资源、灵脉、法阵、火种、神器使用高识别发光材质。
- 剑术轨迹和法术前摇必须比伤害数字更重要。
- 敌我描边、神器脉冲、火种拖痕和危险边界优先于环境装饰。
- 大规模混战时自动降低粒子数量、投影精度和远处材质细节。

具体见《渲染技术方案》。

程序化美术用于扩大内容量和强化肉鸽变化，但它只能生成表现和可读辅助，不能单独生成权威资源、掉落、碰撞或战斗收益。具体见《程序化美术技术方案》。

## 8. 人物方向

人物不是传统职业固定皮肤，而是 **局内身份与装备状态的可读载体**。

技术原则：

- 同一个角色骨架支持轻装、中载、重载、大件搬运、火种携带、神器携带。
- 角色轮廓优先表达战斗状态：轻装快、重装稳、搬运弱、持神器危险。
- 秘剑和法术通过姿态、轨迹、法阵和装备挂点表达，不靠满屏特效。
- 经营皮肤进入对战后必须降噪，不能伪装资源、敌我、火种或神器。

具体见《人物设计与角色技术方案》。

## 9. UI 方向

UI 的核心不是堆信息，而是让玩家知道 **现在能做什么、代价是什么、风险在哪里、目标是谁拿着**。

技术原则：

- 战斗 HUD 极简，优先生命、耐力、法力、负重、保护/PVP、当前目标。
- 资源和地形 UI 只在相关操作时展开。
- 国家指挥和小地图必须能标注火种、神器、阵眼、队伍任务和危险区。
- 所有高风险操作必须显示代价和掉落风险。
- UI 只发 Intent，不直接改权威玩法组件。

具体见《UI设计技术方案》。

---

## 10. 地形方向

地形系统采用 **静态基础地形 + 可编辑覆盖层 + 关键路径保护**。

技术原则：

- 世界不是无限体素，不能让玩家无限挖穿、封路或造高墙。
- 挖沟、筑墙、架桥、修路、符文槽和阵眼都是覆盖层实体。
- 高产采矿来自矿坑模块和采矿槽，不来自任意墙面可挖。
- 服务端校验材料、预算、尺寸、坡度、关键路径和禁区。
- 客户端按覆盖层增量渲染和更新导航提示。
- POI 地基、出生点、王座、Boss 入口和遗迹主路不可永久删除。

具体见《地形系统技术方案》。

## 11. MVP 技术里程碑

| 阶段 | 交付 | 成功标准 |
| --- | --- | --- |
| T0 工程骨架 | workspace、插件、状态、配置加载 | 客户端和 Headless App 都能启动 |
| T1 本地单局 | 移动、采集、背包、基础战斗 | 10 分钟本地局可玩 |
| T2 资源循环 | 资源池、矿坑模块、掉落、回流、审计 | 关键资源不凭空生成 |
| T3 地形覆盖层 | 挖沟、筑墙、桥、道路、禁区 | 能改造但不能封死关键路径 |
| T4 角色表现 | 装备槽、动画状态、负重姿态 | 轻装/重载/搬运/持火种可读 |
| T5 洞穴与材料 | 短洞穴、Boss 召唤、神器材料 | 洞穴能产生高风险材料跃迁 |
| T6 渲染表现 | PBR 环境、资源高亮、法术/剑术 VFX | 混战中敌我和目标可读 |
| T7 UI 闭环 | HUD、小地图、背包、装备、地形工具、国家指挥 | 玩家能理解目标和风险 |
| T8 神器与终局 | 全局唯一神器、封印、王座进度 | 神器改变战略目标但不变成纯数值碾压 |
| T9 公开赛 | 排名、治理权替换、经营入口 | 经营不影响下一场战斗数值 |

更细的阶段顺序、禁止事项、验收门槛和第一周建议见《开发顺序与里程碑》。

## 12. 技术红线

- 不做完整自由体素。
- 不做客户端权威。
- 不做经营战力继承。
- 不做长期装备带入公开赛。
- 不回退到旧版远程武器技术路线。
- 不让神器变成普通装备词条。
- 不让 UI、渲染或动画系统写入权威资源和伤害。
- 不让皮肤破坏 PVP 可读性。
